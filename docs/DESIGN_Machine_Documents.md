### 2.3 Three conflations the forks share, or split on

**(a) Retention: "opts in under `reduce_after_capture.md`" is a category error, and John's 2026-09-29 ruling dissolves it.** game_one's pages say *"exempt from /nodelete by John's ruling … It opts in under `strategic_operations/reduce_after_capture.md`"* (`john_decision_queue.md` header; `decision_queue.py` docstring; registry `retention` fields; `reduce_after_capture.md` §6). That contract is a *deletion-under-ruling* regime for capture surfaces — hand-written bodies that an actor may shed after John rules the list ("John rules the list; an agent never deletes on its own judgment"). A machine document is never deleted by an actor at all; a script rewrites it. Card 21 already noticed the misfit for JSON (*"`cite_fingerprints.json` does not opt in … `reduce_after_capture.md`'s own subject … does not describe this file's shape"*). John's ruling settles it for every machine document: `/nodelete` governs actors (LLMs and users) editing surfaces; a machine document has no editing actor; it is outside the protocol by kind, not exempt by opt-in. §3 draws the consequences.

**(b) "Generated" and "rebuildable" are not the same property.** Card 21 defines *"a page or ledger an agent regenerates on demand, never hand-edits"*. Under that definition `docs/agent/cite_fingerprints.json` is a machine document. But its own card says `--record` *"is the explicit human act"* that clears a drifted edge, and *"an edge already `state: drifted` is never silently re-recorded `current` by `--write`"*. Delete the file and run `--write`: the drifted states and their `recorded_at_commit` history are gone. The file holds human decisions; it cannot be rebuilt from its sources alone. It is a **tool-maintained ledger**, and it belongs under `/nodelete` (Live-State contract — one current state per edge). `docs/agent/contract_index.json`, by contrast, is a pure function of its sources (`contract_index.py` docstring) and is a machine document that simply was never registered. The rebuild test in S1 splits these mechanically; the ticket's "Card 21 second tier" is the symptom of the missing test.

**(c) Source introspection and runtime probing were bundled under one word in ai.** John's mandate is unambiguous and right: *"pull the execution commands from the code base, not hardcoded commands."* Reading `run_gpu.sh` for its flags, `prompt_studio.py` for its port, the commit-msg hook for its categories — that is reading tracked sources, deterministic, and exactly what a machine document should do. A page that carries them is unstable by construction and can never be "fresh" in the byte sense the other two workspaces test — which is why ai could not have a `--check` even if it wanted one. The fix is a vocabulary split (§6: *introspection* of sources is required; *probing* of runtime is forbidden) and a home for the runtime facts (a live command that prints and never writes, or a dated report — §4 S5).

## 3. The anchoring ruling and its consequences

**Ruling (John, 2026-09-29):** *"Machine Documents are exempted completely from the /nodelete protocols. Nodelete applies to LLM's and Users only. This is something else entirely."*

Read precisely: `/nodelete` (`claude-commands/nodelete.md`, "Surgical Scope & Contradiction Protocol") governs what an **actor** — an LLM or a user — may do when editing a **surface**: identify the retention contract, act only on the expressed scope, resolve contradictions by clean replacement, quarantine what is removed. Every one of those verbs presumes a hand on the file. A machine document has no hand on it. The generator is not an actor: it holds no judgment (S6 puts all judgment in a hand-kept file), it rewrites the whole page every time, and the one act the protocol exists to discipline — an edit — is the one act forbidden on the page, erased by the next run.

Consequences, each of which the specification below states as a rule:

1. **No retention contract is identified for a machine document.** It is neither Append-Only Ledger, Live-State, nor Composed Artifact. Its record is its declared sources plus git history of the page. Pillar 1's classification step is skipped by kind, and the `/nodelete` workflow gains one GLOSSARY row and one sentence saying so (§9 PR-2). It does not gain a fourth contract.
2. **No opt-in, no quarantine, no archival ledger.** `reduce_after_capture.md`'s opt-in note (§6, 2026-09-24) described a category the ruling dissolves; game_one's headers and registry `retention` fields drop the opt-in clause and cite the ruling (§8.1). The note itself is append-only and is reconciled by a dated §7, never edited.
3. **Judgment data files stay under `/nodelete`.** `raised_to_john.json`, `decisions.json`, `asset_requirements.json`, the journal's ASK rows: each is authored by an actor, carries its own retention contract (game_two's `raised_to_john.json` schema block is the model: ids never reused, closed items stay as the record), and is edited only through the protocol.
4. **A generated section inside a hand-kept file is outside `/nodelete` between its markers and frozen outside them.** The remainder is protected by Pillar 1's Safety Rail ("never delete a unit the user did not name"); the engine touches bytes between the markers only.
5. **Law about machine documents is hand-kept and under `/nodelete`.** The canonical spec's data file, the binding cards (19, 09), ai's policy page: John locks them; an agent appends dated successors.
6. **A tool-maintained ledger is not a machine document** (S1's rebuild test) and stays under `/nodelete` with the contract its own schema declares.

## 4. Canonical specification, v1

**Carried from the forks because it is proven in two workspaces and tested:** the five header lines; one registry and *"a page not listed is not generated"*; one command with `--list / --check / --write`; whole-page rewrite; byte-identical determinism proven by a double render (`UNSTABLE`); the writer is the dispatcher at a close, never a hook, never a test a peer's commit can redden; judgment lives in a small hand-kept data file; a machine document is not law and not a record and is never cited as authority; its record is its sources plus git.

**Redesigned in this specification:** (1) one shared engine in the suite instead of one copy per workspace; (2) the `/nodelete` relation — outside by kind, no opt-in; (3) the rebuild test as the definition, which separates tool-maintained ledgers from machine documents; (4) an explicit ban on clocks, the current commit hash and runtime probes, with a named home for runtime facts; (5) an `audience` field and a staleness measure in source commits, with a rule tied to audience; (6) a declared `section` form for hybrid files; (7) a registry that carries its `spec_version` and its workspace binding; (8) a metric table with a mechanical check per row and a read-only conformance checker that discloses its denominator; (9) one vocabulary; (10) the suite adopts the practice on its own surfaces.

Rules are numbered S1–S12 so a card, a header, a test or the checker can cite them.

### S1 — Definition and the rebuild test

A **machine document** is a file, or a marked section of a file, whose entire content is a deterministic function of declared sources, produced whole by a registered generator, and never edited by any actor.

**The rebuild test (mechanical, decisive):** delete the document, run the registered generator, compare with the committed bytes. Equal → it is a machine document. Not equal → it is not, whatever its header says. A file that holds any state that an actor put there through a tool (a `--record`, a status flip, an id that must never be reused) fails the test and is a *tool-maintained ledger* (S2).

### S2 — The three kinds of file (the vocabulary's spine)

| Kind | What it is | Who may change it | Under `/nodelete`? | Examples measured |
|---|---|---|---|---|
| **Machine document** | Passes S1. Page (Markdown), data (JSON/YAML), or section. | The registered generator, run by the registered writer. A hand edit is erased by the next run. | **No** — outside by kind (§3). | game_one `meta_contract.md`, `contract_index.md`, `contract_index.json`; game_two all eight registered pages; ai `PORT_REGISTRY.md` (after S5), `README.md` command section (after S7). |
| **Hand-kept surface** | Authored by an actor. Includes **judgment data files** (the small file a generator reads for what only a human decides) and **tool-maintained ledgers** (state written through a CLI on a human's act). | An LLM or a user, through the protocol. | **Yes** — with its own retention contract. | `designer_intent.md`, every `*_contract.md`, `raised_to_john.json`, `decisions.json`, `asset_requirements.json`, `cite_fingerprints.json`, the cards, the spec's data file. |
| **Report** | A dated measurement of a moment: runtime state, a maintenance pass, an audit. Written once, never regenerated in place. | The tool that took the measurement. | Yes — Append-Only Ledger or immutable file. | game_one `strategic_operations/reports/*`, `staleness_ledger.md` rows, this suite's receipts; ai's live port/VRAM status once moved out of its pages (S5). |

### S3 — The label

**Markdown page or section — five lines, in the first 40 lines (of the file, or of the section after its begin marker), keys read by machine, prose free:**

```
**Status: generated — not law, not a record.**
**Built from:** <the sources, by path or glob, exactly as the registry declares them>
**Regenerate:** `<binding.regenerate_command> --write <name>`
**Retention:** outside /nodelete by John's ruling 2026-09-29 (machine documents have no editing actor) and <the workspace ruling: date, journal or ledger pointer>; content that stops being true is dropped at the next run; the record is the sources and git history.
**Hand edits:** none. The next run overwrites them.
```

Canonical grammar (the strict form; game_two's regexes, which every page in both workspaces already satisfies today — game_one's registry carries no `header: legacy` entry any more):

| Key | Regex (searched in the first 40 lines) |
|---|---|
| `status` | `^\*\*Status: generated — not law, not a record\.\*\*` |
| `built_from` | `^\*\*Built from:\*\*` |
| `regenerate` | `^\*\*Regenerate:\*\*` |
| `retention` | `^\*\*Retention:\*\*` |
| `hand_edits` | `^\*\*Hand edits:\*\* none\.` |

The line `**Status: generated — not law, not a record.**` is **the mark**. The mark is a token, not vocabulary (§6): it stays byte-identical across every workspace so one regex finds every machine document everywhere. A tolerant match (`Regenerate with`, `Never edit by hand`) is reported `LEGACY`, never silently accepted.

**JSON or YAML data — a top-level `_meta` object with the same five keys:**

```json
"_meta": {
  "status": "generated — not law, not a record.",
  "built_from": "…",
  "regenerate": "… --write <name>",
  "retention": "outside /nodelete by John's ruling 2026-09-29 …",
  "hand_edits": "none. The next run overwrites them."
}
```

game_two's `_header` (an array of the five Markdown lines) and game_one's current `_meta` (`generator`, `regenerate`, `status`, `reduce_after_capture`) are both reported `LEGACY` until migrated. JSON never carries Markdown bold markup (contract_index.py's docstring already refused that leak, correctly).

**Section form — markers around the generated block inside a hand-kept file:**

```
<!-- machine-document: begin <name> -->
**Status: generated — not law, not a record.**
… (the other four lines, then the body)
<!-- machine-document: end <name> -->
```

For a non-Markdown host the registry entry declares its own `begin`/`end` strings (this suite's `.gitignore` uses `# >>> Sovereign Suite — managed block … >>>` / `# <<< … <<<`, already in force since 2026-07). The label travels inside the section.

**Anchors [ADDED 2026-09-30 — discussion pass, John zero dissent].** A machine document that others link to by `path#anchor` keeps its anchors stable across regeneration: every `{#anchor}` a generator emits derives from a stable identity in the sources (a contract's file stem, a journal row's `GDI-n`, a card number, a registry `name`), never from position, order or a running count. An anchor changes only when the source identity changes, and a rename of a minted anchor goes through the workspace's own remint rule (game_one card 18; `contract_style.md` §6.13), not through a rerun. The checker compares the anchor set of the committed document with the anchor set of the render and lists every anchor that disappeared (`ANCHOR-DRIFT`, M15). Without this rule a rerun can silently break every citation into the page, and a fingerprint ledger keyed on `path#anchor` (game_one's `cite_fingerprints.json`) reports drift on every regeneration for no reason.

### S4 — The registry

One file per workspace, the only list of machine documents; a file not in it is not one. Canonical name `machine_documents.yaml` at the workspace's governance root (R3); the engine takes `--registry` and accepts the current `generated_surfaces.yaml` / `surfaces:` key as `LEGACY` for one spec version.

### S5 — Sources, determinism, and the line between introspection and probing

- **A source is a file in the workspace tree**, tracked by git, or an untracked path declared in `untracked_sources` (the checker then reports that the page is not reproducible from history alone — a caveat, not a failure).
- **Introspection is required where the fact lives in code.** A command, a flag, a port, a hook's rule, a contract's status line, a file's executable line count: read it from the file that owns it (AST, regex over the file, `git ls-files`). A typed-in copy of a fact that lives elsewhere in the tree is the failure ai's policy names, and M5 measures it.
- **Forbidden inside a machine document:** the wall clock (any `datetime`/`time` value); the current `HEAD` hash; any runtime state — processes, sockets, hardware, network, environment variables; filesystem enumeration order (sort everything). A value from git *history about a source* (a source's last-change date) is permitted: it changes only when the source changes.
- **Runtime facts get a named home.** A *live command* that prints to stdout and writes nothing (`scripts/live_status.py` in ai: ports listening, VRAM free), or a *report* (S2). Never a machine document.
- **A source is never another machine document [ADDED 2026-09-30].** A generator reads records — the journal, the contracts, the judgment data files, the code — never another document's projection of them. game_two already works this way by instinct (`gen_decision_queue.py` recomputes the doc-health checks instead of reading `doc_health.md`; `gen_doc_health.py` excludes every registered page from its scan). The rule makes it law and removes any need for a regeneration order or a fixed-point loop: with no generated-reads-generated edge, `--write --all` is order-independent. A declared source that resolves to a registered document is `SOURCE-IS-GENERATED` (M14); the fix is a narrower glob or an `exclude:` list (S4).
- **Same sources → same bytes.** The engine proves it by rendering twice (`UNSTABLE`), and the checker proves the stronger property by the rebuild test (`--deep`, M13).

### S6 — Judgment lives in data

A page whose content needs an agent's or John's judgment is not generated whole. The judgment lives in a small hand-kept data file the generator reads; only the rest is generated. A judgment data file carries a `schema` block naming its consumer page, its fields, its status enum and its rules (game_two's `raised_to_john.json` is the reference shape). The three John-queue schemas that exist today are not unified by this design (§13, captured).

### S7 — Scope: what may be a machine document, what never is, and hybrids

- **Candidate:** any file every fact of which is derivable from other files in the tree. Card 19's and Card 09's word "as many as logical" is the scope; ai's "EVERY document" is corrected to it (R11), because `designer_intent.md` — John's verbatim words — can never be derived from anything.
- **Never a machine document, in any workspace:** designer-intent journals and any verbatim capture of John's words; locked contracts and any page with a `Status:` token that decides something; ledgers, receipts, execution logs, `PROCESS_LEARNINGS.md`, `.history/**`; anything another surface cites as evidence; a law or policy page (a machine document "is not law"); `CLAUDE.md`, `AGENTS.md`, `README.md` **wholesale**.
- **Hybrids:** a hand-kept file may host one or more generated sections (S3 section form), each registered with `format: section`. This is how `README.md`'s command block, `CLAUDE.md`'s contract rows, `AGENTS.md`'s LOC table and this suite's `SUITE_HEALTH.md` delivery-surface table become true by construction without generating the judgment around them.

### S8 — Who writes, when, and what the command says

- The **writer** is the role the binding names (the dispatcher, the orchestrating session, `/secretary` at close), in its own checkout. A fork or subagent never writes a machine document unless its declared write-set names it. Not a commit hook (worktree fan-in collisions, the cards' reasoning stands); not a test that a peer's commit can turn red.
- **Verdict grammar** (stdout, one line per document, tab-separated, machine-parsed by the checker): `<STATE>\t<name>\t<detail>`. Engine states: `fresh`, `STALE`, `MISSING`, `UNSTABLE`, `HEADER`. Checker-only states are listed in §5.
- **Exit codes:** `0` every selected document fresh / written; `1` at least one FAIL-class verdict; `2` usage or registry error (an unknown name, a missing required field, an unreadable registry) — and nothing is written on `2`. `--write` is all-or-nothing per invocation (game_two's semantics): every selected page renders and passes M1 before any page is written.
- **Failure semantics [ADDED 2026-09-30].** A generator that raises during `--check` or `--write` yields the state `ERROR` for that document, with the exception's first line as the detail. Under `--write` the all-or-nothing rule extends to exceptions: nothing is written for any selected document; exit `1`.
- **Scaffold [ADDED 2026-09-30].** `regenerate.py --new <name> --path <path> --format <fmt> [--kind <kind>] [--audience <a>]` writes, in one pass and nowhere else: a generator stub under the binding's `import_roots` that already emits the five label lines and reads one declared source; the registry entry; a labelled skeleton at `path` (or the marker pair for a section); and a fixture test asserting freshness, negative drift and determinism. Adding a document is one command plus the generator's body, not four hand steps copied from the previous page — the per-document form of the same Fork-by-Copy the ticket is about.

### S9 — Audience and freshness

- `audience: john` — a page John reads (queues, dashboards, order sheets). `audience: agent` — read by agents at session start or during work. `audience: machine` — read by scripts (JSON ledgers, indexes).
- **Staleness is measured in source commits, not days:** `stale_by = commits touching any declared source since the document's last commit`. The checker prints it with the oldest such commit's date. (Days-since-audit stays MI-1's minted sense in game_one and is not reused.)
- **Rule:** at every close the writer runs `--check --all` and `--write` for the stale documents. A `john`-audience document with `stale_by > 0` at a close is a FAIL (`JOHN-STALE`, exit 1 under `--at-close`); at any other moment it is reported, not failed, because in-flight staleness between closes is the design. `/sentinel` reports `JOHN-STALE` documents at session start so the next agent regenerates before John reads (§9 PR-2). No hook; the alternative (a pre-push check) is R7's alternative.
- **Register [ADDED 2026-09-30].** `audience` also fixes the register a generator writes in: `john` → plain language, no unexplained token, choices and recommendations stated (ai's `REGISTER = f(audience)` rule and game_one's "For John, in plain words" blocks are the two existing forms); `agent` and `machine` → dense, anchored, token-exact. The kinds spec records the convention per kind (S13); it is a rendering rule, not a checker metric.

### S10 — One engine, per-workspace bindings

The engine — load the registry, render, verify the label, compare bytes, double-render, write atomically, splice sections — lives once, in this suite: `~/blueprint-workflows/scripts/machine_documents/`. Generators, registries and judgment data stay in the workspace. A workspace binds by its registry's `binding` block; a thin in-repo shim (`strategic_operations/tools/regenerate.py` in game_one, `scripts/generated/regenerate.py` in game_two) may remain so that the `Regenerate:` line on every page keeps working and the workspace's interpreter is the one that imports its generators. Path resolution follows `role.md`'s Script path resolution constant (absolute `~/blueprint-workflows/scripts/...`), the same way every other engine in this suite is invoked from any workspace.

**Engine security [ADDED 2026-09-30].** The engine imports and executes workspace Python. It imports a generator only from a module path that resolves inside the binding's `import_roots`, each root asserted within the workspace (`engine_utils.assert_within`); it refuses a generator whose resolved file lies outside the workspace; it never follows a symlink out of the tree; and the checker never imports a workspace generator into its own process (§7). A `/harden` grade on `scripts/machine_documents/` is a PR-1 acceptance criterion, not a follow-up.

### S11 — Versioning

The registry declares `spec_version`. The engine and checker declare the version they implement. Older → `LEGACY` warnings and a migration hint; newer → refuse (`SPEC-VERSION`, exit 2). The canonical spec page itself records its version.

### S12 — Not law, not a record

A machine document decides nothing and is never cited as authority; its sources are. It carries the mark so that a reader knows this before reading the first fact. (Verbatim from Card 19's invariant; kept as a rule because it is the reason a law page can never be one — §2.4.)

### S13 — Kinds [ADDED 2026-09-30]

A registry may declare **kinds**: one entry per kind of hybrid file, matching a glob, never one entry per file. A kind declares which parts of a matching file are generated sections (S3 section form); which header field is the file's Live-State status slot and its allowed states; the transitions between states and what each requires; whether the body is guarded once a terminal state is reached; and the audience and register of the generated parts. The body of a kind's file is hand-kept and under `/nodelete`; only the declared sections are machine documents. The first kind is `contract` (§14). A kind's mechanics live in the suite's spec data and are consumed by every workspace's binding, so a ceremony is one process everywhere. The prose law of the kind — game_one's `contract_style.md`, game_two's `CONTRACT_STYLE.md` — stays in the workspace, hand-kept, and is not restated in the spec: if a kind entry starts carrying sentences about how to write a contract, it has crossed that line.

**CLI:**
```

  --workspace /abs/path [--registry machine_documents.yaml] [--at-close] [--deep] [--output-json] [--quiet]
```

`--at-close` promotes `JOHN-STALE` to FAIL (the writer's and `/secretary`'s mode). `--deep` runs M13 in a scratch copy under `tempfile` (never in the tree). **[2026-09-30]** `--kinds` adds the kind-level rows M17–M19 over every file a kind's glob matches; the denominator line then also states how many files each kind matched and in which states. ## 14. Kinds and the contract lifecycle [ADDED 2026-09-30 — discussion pass; John: *"I have zero dissent with your output in full. fold them in."*]

John's question of 2026-09-30, verbatim in its load-bearing part: *"Is there a way in this design to use the local workspace file to generate a new document, with a flag similar to --draft for locking, and then when we are ready to lock it, we change the flag to --locked in the local file, so the machine substrate knows that file is locked, and when generated fresh, always regenerates the locked? This will save from the non stop bloat of strikethrough and superceded accross the contracts."*

The answer is two things, kept apart because they have different levers.

### 14.1 The bloat is a retention reading, not a generation problem

Measured 2026-09-30, read-only:

| Workspace | Contracts | Files with `~~` spans | Lines with `~~` | Bytes on those lines | "supersed" mentions |
|---|---|---|---|---|---|
| game_one | 223 | 198 | 3,769 | 556,084 of 9,248,528 | 1,268 |
| game_two | 97 | 96 | 872 | not measured | 230 |

The residue is produced by rule, not by accident. game_one `contract_style.md` §2.1: *"Exactly one live status line. Prior statuses are struck in place and kept."* §2.4: *"1. Strike the old line with `~~...~~`. 2. Immediately below, a blockquote … plus one sentence of why"* and *"Agents: do not 'clean up' struck history. That is a style violation equal to inventing a lock."* Its §6.2 row, amended 2026-09-23 by John's direction: `docs/**` *"is struck and kept, never quietly erased."* game_two Card 01's invariant: *"the superseded block stays unedited at its own site as the dated record."* None of that is `/nodelete`; it is one workspace's reading of it, copied to the second — the same Fork-by-Copy shape as the machine-document cards. The suite's own Pillar 1 already provides the ghost-free form. A **Live-State** surface resolves a contradiction by clean replacement: *"Delete the old value, write the new, verify it is faithfully captured. One current value per slot. No inline ghost, no 'superseded' note."* An **Append-Only Ledger** holds the history. So: a contract body is Live-State; its changelog is Append-Only; the old text's record is git plus one dated changelog line. That is R12, and it needs no code.

The cleanup of existing residue already has a mechanism in game_one: `reduce_after_capture.md` §2 names *"Ceremony strike residue — `~~struck~~` header lines from a recharter → collapsed to the clean successor + one dated changelog line"* as a deletable class; `bypass_audit.py` lists candidates and never deletes; John rules the list; the pass receipt names every span's distilled home (*"ruling before rescue, rescue before deletion"*). game_two has no equivalent — its own survey of 2026-09-24 says so — which is why PR-8 adds a read-only lister (§14.6) that produces the same ruled list there.

**Dissent, recorded.** Contracts are not made machine documents to escape the bloat. A contract is law; law is judgment on every line; John's ruling of 2026-09-29 puts machine documents outside `/nodelete`, and law must never be outside it — a regenerator would then be able to rewrite law. S7 (never a machine document: locked contracts, a law or policy page) and S12 stand unchanged. What is generated is everything *about* a contract that is mechanical.

### 14.2 The lifecycle flag: where it lives, and what "always regenerates the locked" means

The flag John describes already exists: the two status tokens, `draft for lock` and `locked YYYY-MM-DD`, on the contract's own status line (`contract_style.md` §2.1, "the legal switch"; Card 01: *"status is a property of a statement, not of a file — read the header AND the heading"*). Under R12 that line is a **Live-State slot in the file itself**: flipping the flag is a clean replacement of one value, and the lock transition writes a **lock record** once — lock word, date, GO id, token prefix — into the header stack.

It is not a per-file line in the registry. The registry gains one `kinds:` entry for the contract kind (S13; S4's example), matching `docs/design/*_contract.md` and declaring:

- **Generated sections** (S3 section form; marked; regenerated every run from the file's own header fields and body facts): `contract-header` — the status line rendered from the status slot and the lock record; the open-items count *counted* from the body, never typed; the token line; the cited-by count from the link graph; the per-state fixed sentences the style guide prescribes ("Locked does not mean built", the draft obligations). `contract-changelog` — rendered from the Append-Only changelog list, newest last. `vnext` — the `## vNEXT — PLAN, NOT LAW` scaffold, present iff `locked`, every line carrying `~PLAN~`.
- **Transitions and requirements.** `draft-for-lock → locked` requires the lock word (verbatim, John's), a date, a GO id, zero open items or a listed set, and a minted token prefix. `locked → superseded` requires a successor path and a ruling — which is exactly `version_bump_contract.md`'s **VB3/VB6**: a +1.0 bump forks a successor file and the predecessor is neither edited nor renamed. **VB1** (in-place amendment, version unmoved) becomes the R12 form: clean clause replacement plus one changelog line. **VB2** (+0.1 forced) moves the status line only, as today.
- **The lock guard (M17).** Once `locked`, the body outside the generated sections is compared at HEAD with its bytes at the lock commit; a change with no changelog entry dated after the lock is `LOCK-BREACH` at close. This is the mechanical meaning of "the machine substrate knows that file is locked": a hand edit to the header is overwritten by the next run, because the sections are machine documents; a silent edit to the body is named by the checker.

"When generated fresh, always regenerates the locked" therefore holds for the header, the changelog rendering and the vNEXT scaffold — the parts that were accumulating residue — while the law text itself stays hand-kept, byte-frozen by the guard, under `/nodelete`.

### 14.3 What is executed today versus prose

`contract_style.md` says of itself that nothing in it is enforced by an executing check except §6.8's two rules, and names that *"the defect class this workspace has already paid for."* `tests/test_version_bump_v0.py` asserts exactly VB7 (the per-line `~PLAN~` marker) and VB8 (no plan section in a draft) over `docs/design/`. Card 01's `checks:` reads *"none yet — this workspace has no contracts to check against"* while 97 exist. The kind turns §2.1 (one live status line), §2.4 (history form), §6.8 (vNEXT), VB6 (successor, not rename) and the lock ceremony's requirements into M17–M19 — executed in both workspaces from one spec, with each workspace's prose law untouched and its existing test kept as a local oracle.

### 14.4 Why not generate whole contracts from a structured source

Considered and not recommended: a `contract.yaml` clause list rendered into the `.md`. Prose law — the style guide's §3 body sections, findings, walkthroughs, "what this lock did not decide" — does not survive a clause list, and every contract would become two files with no derivation gain over the section form. Data-shaped contracts (game_two's asset catalogue and order sheet; ai's port allocations) are already data plus a generated page, and that is where whole-file generation belongs.

### 14.5 Register and audience for the kind

The contract kind's generated sections are `audience: agent`, `register: LLM→LLM`. A `john` audience is never assigned to a contract section: the plain-language surface for John is the queue, not the law (S9's register rule).

### 14.6 The residue lister

`scripts/machine_documents/residue.py --workspace <path> [--glob "docs/design/*_contract.md"] [--output-json]` — read-only. For every matching file it lists each `~~struck~~` status line and each SUPERSEDED / AMENDED / PROMOTED blockquote with its line number, its bytes and the changelog line it would collapse to; totals per file and per workspace; the Denominator Disclosure line first (files matched, files skipped, bytes examined). It lists; it never deletes — the same posture as `bypass_audit.py`, whose "Ceremony strike residue" class it reproduces for a workspace that lacks it. John rules the list; the collapsing pass is a ruled pass with a receipt naming every span's home; the collapse itself is a hand act under `/nodelete` (the body is hand-kept), never a generator's.

## Independent Critique (native path — `/quality` Step 5 adversarial self-critique; no Grok delegation)

**Objection 1 — "A shared engine makes three independent repos depend on this one."** They already do: every Sovereign workflow they run invokes `~/blueprint-workflows/scripts/...` by the Script path resolution constant, and the delivery-surface engine populates their `.agents/workflows/` from here. The design adds a versioned data contract (`spec_version`) and keeps each workspace's command line unchanged through a shim. The alternative — three engines — is the measured failure.

**Objection 2 — "Banning runtime probes contradicts John's 'dynamically machine generated' mandate."** His words are *"pull the execution commands from the code base, not hardcoded commands."* Code is a source; the design makes reading it mandatory (S5, M5). A socket's state is not in the code base. The mandate is preserved exactly; only the over-extension is removed, and the runtime facts get a home rather than being dropped.

**Objection 3 — "Measuring staleness in commits is workspace-dependent; four commits is nothing in game_one and a week in ai."** Correct, which is why `stale_by` is a measurement and not a threshold. The rule is audience-based and event-based — a John-facing page is fresh at a close — and the measurement is printed so a reader can judge the lag in the workspace's own rhythm.

**Objection 4 — "Sections reintroduce the hand-edit risk the practice exists to remove."** A section is byte-checked exactly like a page (M2 over the bytes between markers), M8 detects a hand edit inside it, and the remainder is frozen by the Safety Rail. The suite's `.gitignore` block has run this way for two months without a reported drift. The alternative — splitting on a heading string, as ai does — is the unmarked version of the same thing.

**Objection 5 — "M5 will punish every generator that has an introduction."** It is WARN-class, the header is excluded, the threshold is John's, and the largest literal is printed. Its purpose is the case the ai policy names and instantiates — a page that is 90 percent literals wearing a generator's clothes — and that case sits near 1.0, nowhere near a headline and two sentences.

**Objection 6 — "Isn't this design itself a fourth fork of Card 19?"** No, and the difference is the mechanism: Card 19 becomes a *binding* that consumes a spec held as one locked data file, and a checker compares every binding against it. A fork is a copy nobody compares; this is a source everybody is compared to.

**Objection 7 — "The checker could pass vacuously, exactly the open meta ticket's class."** Designed against by construction: the denominator line is the first line of output, `NO-REGISTRY` is a failure when mark-carriers exist, and `test_machine_documents_audit.py` carries a zero-denominator fixture that must not print PASS. That fixture is the acceptance criterion, not a note.

**Objection 8 — "Reclassifying `cite_fingerprints.json` narrows Card 21 after the fact."** It does, by a test the card lacked. Card 21 itself already hedged (*"cite_fingerprints.json is data, not prose"*; *"only `--record`, the explicit human-confirmed act, may clear it"*). S1 makes the hedge a rule. R8 puts it to John rather than asserting it.

**Objection 9 — "Kinds turn the registry into a second style guide."** *[2026-09-30]* No: a kind declares mechanics — which sections, which slot, which transitions, which guard — and the prose law of the kind stays in the workspace's own style guide, not restated. S13's last sentence is the test: a kind entry that starts carrying sentences about how to write a contract has crossed the line.

**Objection 10 — "Anchor stability freezes bad anchors forever."** *[2026-09-30]* It freezes them across *regeneration*. A rename is a source-identity change and goes through the workspace's remint rule (card 18; `contract_style.md` §6.13), which is where a rename belongs. The failure the rule prevents — every rerun silently breaking every citation into the page — is worse than a stable bad anchor.

**Objection 11 — "R12 overturns a direction John gave six days earlier."** *[2026-09-30]* It does, and it says so at its own site: §2.4's rule and the §6.2 amendment are struck and succeeded once, by his direction, in game_one's file — the very form R12 retires, used one last time to record its own retirement. His 2026-09-30 zero-dissent is recorded in §10; the workspace capture is still PR-0's act in each workspace, not this document's.

**What this critique did not resolve:** whether the pre-push alternative in R7 is wanted for the John-facing pages specifically, and whether the health-index table should wait for a `standard_version` field or drop the column — both are John's, and both are in §10.
